### 3.3 Topic 3 – Committing and Reviewing Code  
Raised by Daniel.  
**Summary:**  
- Small things are being overlooked and merged, building up to an insignificant time requirement to resolve issues before a sprint release.  
  **How to Solve?**  
- Acknowledge that it is challenging to identify every small thing.  
  
*For authors:*  
1. Build the app. (compile-time)  
2. Try everything implemented. e.g. added a schema query? ensure running the app creates the table. added logic to answer a quiz question? run the app and answer the question in every combination to ensure it works. (runtime)  
3. Check console/terminal afterwards to check for anything caught by the global exception handler, e.g. incorrect javafx version in xml namespace  
- Ensure everything works at final commit  
  
*For reviewers:*  
- Check Github action workflow runs successfully (this is enough, you don't need to checkout and run yourself as this is the point of it)  
- Raise anything that looks sus (BE CRITICAL, WE ARE ALL AWARE IT'S JUST A PR COMMENT, NOT A PERSONAL ATTACK!)  
- Recommend alternate solutions if any  
- Do not approve something that hurts long term, e.g. implementing large changes to temporarily make a unit test work.  
  
*Steps to run branch locally.*  
- `git status -sb` to ensure no uncommitted code in local repo beforehand.  
- `git fetch` to get branches from remote repo.  
- `git checkout branch-name` to switch to PR branch.  
  Steps after:  
- `git switch dev` to return to dev branch.  
- `git branch -D branch-name` to delete branch you were just looking at.  
- `git fetch --prune` to remove local references to branches that have already been deleted from the remote repository.
