## Abstract:
Derived from Atlassian's article [here](https://www.atlassian.com/agile/scrum/sprint-planning), Sprint planning is a preparation process for an upcoming event called a sprint. Process involves identifying what tasks will be completed in the sprint and how that work will be achieved.

Benefits of this process include the team fully understands what need's to be accomplished during sprints. Increasing focus, helping the team break stuff down in to smaller, manageable tasks. and align on priorities.

Recommendations for this plan include:
- Agreed start and finish dates for the proper "Sprint 1". We just retroactively 
- What are we focusing our attention on in the program and how we are splitting up the work.
- Stepping stones for what work should be done first.

## Sprint 1

### Objectives:
This sprint two epics (groups):
#### Epic 1: ==Front-End Prototype's==
Justification:
To establish a shared visual foundation for the application before development begins, ensuring all team members build toward a consistent and user-focused interface.

| Issue # | Action-item            | Reason                                                                                        |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------- |
|         | Figma Med-Fi Prototype | To give the team a shared visual reference prior to coding.                                   |
|         | Stylesheet             | To establish consistent visual language i.e. colours, typography, spacing across all the app. |
|         | Page Mapping           | To document every screen and respective origin/destination points in the program.             |

#### Epic 2: ==Technical Planning==
To define the structural and data architecture of the application early, giving the team a stable technical foundation to develop against and minimising costly rework in later sprints.

| Issue # | Action-item               | Reason                                                                                                                                                                                                         |
| ------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|         | Class Diagram Iteration 4 | To demonstrate iteration-based objectives adhere to our programs requirements continuously, providing developers a stable object-oriented blueprint and evidencing the iteration required.                     |
|         | Database Schema           | To establish agreed data structures early so all team members share the same assumptions about storage, enabling front-end and back-end to continuously develop separately and without breaking changes later. |
