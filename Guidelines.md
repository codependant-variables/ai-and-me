## 1. GitHub projects
Projects was designed to include the following sorting conventions:
- **Draft/Issue name** (Self explanatory) - Stick to a naming scheme similar to others, add your explanations/purpose to the comments section in your draft issue.

-  **Assignee:** (Who's responsible for implementing it)
	- Image:![[Assignees.png]]
-  **Status:** 
	- **Purpose:** Keeps track of the item in the pipeline
	- **Conventions:** 	![[Status-Convention.png]]

-  **Liked Pull requests** (Don't worry about this until we are concluding a feature.)
	- **Note**: Pull requests only start once a feature(branch) is wanted to be brought into the dev branch of the program.

- **Sub-Issues progress**: For having multiple incremental problems to solve to implement a feature.
	- **Example**: You implement a UI, but you need a database to store the data entered. make the UI a Sub-issue, and the DB another...
	- Image: ![[sub-issue-expand.webp]]

- **Iteration**: Is a feature to allow you to plan and track your work within time blocks. 
	- Example. Maybe in the first half of a week, you are implementing user acceptance criteria to accomplish a user story. However no matter how far you get. you may need to test it to make sure your existing code is running without bugs.
	- Image:![[iteration-insert-break.webp]]
- **Label type:** another way to organise stuff meaningful way, so we don't bunch User Stories, drafts of User stories, and Housekeeping items.
	- Conventions:![[label-type.png]]
- **Start Date:** This helps the rest of the team see how you are travelling since said date.
	- The team can set a start date so they can keep track of how long they have spent on a "Issue"

**NOTE**:
When adding to projects, please add as a DRAFT first. tag it accordingly, and please consider simplifying what you intend to do, if you end up requiring assistance. it may be challenging for others to understand.

**NOTE 2**: When creating a feature, check if their isn't already something there. i.e. a user story or a sub issue already there...

**NOTE 3:** When reaching a point where your branch has the necessary user acceptance criteria and functionality, along with your individual tests, Re-tag the status of your "Issue" in projects from "In Progress" to "In review" that way we are aware of what features, bugfixes, should be endorsed for end of our sprint milestone
