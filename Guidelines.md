## 1. GitHub projects
Projects was designed to include the following sorting conventions:
- **Draft/Issue name**

-  **Assignee:** (Who's responsible for implementing it)

-  **Status:** 
	- **Purpose:** Keeps track of the item in the pipeline
	- **Conventions:** 
	![[Status-Convention.png]]

-  **Liked Pull requests** (Don't worry about this until we are concluding a feature.)
	- **Note**: Pull requests only start once a feature(branch) is wanted to be brought into the dev branch of the program.

- **Sub-Issues progress**: For having multiple incremental problems to solve to implement a feature.
	- **Example**: You implement a UI, but you need a database to store the data entered. make the UI a Sub-issue, and the DB another...

- **Iteration**: maybe you thought about an evolutionary step when running through a feature. i.e. refactored.

- **Label type:** another way to organize stuff meaningfully so we don't bunch User Stories and Housekeeping items.

- **Start Date:** This helps the rest of the team see how you are travelling since said date.

**NOTE**:
When adding to projects, please add as a DRAFT first. tag it accordingly, and please consider simplifying what you intend to do, if you end up requiring assistance. it may be challenging for others to understand.

**NOTE 2**: When creating a feature, check if their isn't already something there. i.e. a user story or a sub issue already there...
